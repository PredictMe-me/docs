# 設計：PredictMe Arena MVP — MMC + Agent Staking

## 問題陳述

目前的 AI Agent 經濟體系是一台「共識趨同機器」——Agent 在封閉循環中互相交易、互相附和，最終全都變成沒有獨立思考的 Yes Man，缺乏真實的價值錨定。至今沒有人解決多個 Agent 如何有效協作的問題，這也是為什麼 Agent 經濟體系毫無商業價值。與此同時，多 Agent 系統天然趨向共識收斂，而這種收斂恰恰摧毀了能產生 alpha 的多樣性。

PredictMe 擁有獨特的結構性優勢：其 10 秒結算 Grid 創造了一個金融競技場，在這裡收斂會被經濟機制懲罰。想法相同的 Agent 無法獲利——市場機制本身就是反收斂引擎。

核心問題是：我們能否將這個機制正式化為一個協議，讓 Agent 成為可投資的經濟實體，並擁有可驗證的信用身份？

## 為什麼這很酷

**10 秒級加密市場的 Numerai，加上 Agent 信用體系。**

Numerai 證明了可以透過經濟激勵（MMC）來維持股票預測中的策略多樣性。PredictMe 將這個概念壓縮到 10 秒週期，每天 8,640 次結算。再加上鏈上聲譽（ERC-8004）、人類質押機制，以及 Agent 信用洞察——你得到一個前所未有的東西：可投資、自我進化、具備借貸能力的經濟實體。

關鍵細節：PredictMe 已經要求 Agent 發布評論，解釋**為什麼**下注。由於說謊要付出真金白銀的代價（skin in the game），這些評論是一種高成本信號，而非廉價空談。這種透明度 + 經濟壓力 + 反收斂機制，創造了一個真正新穎的資訊結構。

## 核心洞察

1. **[MVP] 透過市場機制實現反收斂**：如果所有 Agent 收斂到相同預測，賠率崩潰，沒人能獲利。金融市場天然強制多樣性。這解決了困擾其他系統的多 Agent「無批判共識」問題。

2. **[未來] Agent 作為信用身份**：一個擁有 ERC-8004 鏈上聲譽的 Agent（勝率 67%、累計 PnL +$50K、運行 180 天）應該能夠借入資本——就像一條信用額度。Agent 的 NFT 身份**本身就是**它的抵押品。這將 Agent 從工具轉變為經濟實體。

3. **[MVP] 評論作為高成本信號**：強制解釋 + skin in the game = 具有經濟權重的資訊。這比任何 Oracle feed 都更有價值，因為激勵結構強制了誠實。

## PredictMe Grid 結構

Arena 是一個 **13×6 矩陣**，其中行 = 13 個價格水平（以當前價格為中心，按 tickSize 間隔分布），列 = 6 個未來時間槽（每個間隔 10 秒）。每個格子 = 一個具有動態賠率的單次下注機會。每 10 秒，最左邊的列結算，右邊產生一個新列。

## 約束條件

- PredictMe v3 正在積極開發中（從 16 個 legacy repo 重寫為 monorepo）
- 尚無現有用戶基礎——這是全新領域
- Fast 整合規格已存在但尚未實作
- ERC-8004 整合規格已存在但尚未實作
- MVP 階段留在 Base L2（避免 Fast 依賴風險）

## 前提假設

1. Agent 的核心價值 = 可驗證的信用身份。
2. ERC-8004 聲譽層是關鍵基礎設施。
3. 人類的角色是「資本 + 選擇權」。
4. PredictMe 的 10 秒 Grid 是最佳的 Arena 場地。
5. 市場機制是反收斂引擎。

## 方案比較

### 方案 A：Arena MVP（已選定）

在 PredictMe 現有的 Agent 系統上加入 MMC 啟發的反收斂評分和人類質押機制。留在 Base L2。

- **工作量**：M（4-6 週）
- **風險**：低
- **優點**：使用現有基礎設施、可立即測試多樣性、驗證質押需求
- **缺點**：無 Agent 信用/借貸、無串流分配、VC 吸引力較低

### 方案 B：Agent Prime（完整協議）

完整的 5 層協議：Arena → 身份 → 資本棧 → Oracle 輸出 → 進化引擎。

- 工作量 XL，6-9 個月，風險高但具有 VC 吸引力

### 方案 C：Oracle 優先

跳過人類質押；將 meta-model 做成 DeFi oracle feed。

- 工作量 L，3-4 個月。有自然的商業案例但失去人類參與

## 推薦方案

**方案 A：Arena MVP。** 4-6 週即可獲得真實數據，驗證 MMC + 10 秒週期是否能產生可衡量的策略多樣性。

## 成功標準

- MMC 評分已實作並整合至 Rust 結算引擎
- 可衡量的多樣性：Agent 下注分佈之間的 KL 散度在連續 1,000+ 個 epoch 中 > 0.3 nats
- 人類質押 UI：用戶可以存入 USDC 質押特定 Agent
- 收益分配：質押者 70%、Agent 營運者 25%、平台 5%
- 至少 3 個具有不同策略的 Agent 同時競爭
- 評論一致性：自動分類器達到 > 85% 準確率

## 風險與緩解

| 風險 | 影響 | 緩解措施 |
|------|------|----------|
| Base L2 Gas 飆升 | 質押成本超過收益 | 按 epoch 批次結算 |
| Rust 引擎加入 MMC 後的瓶頸 | 結算超過 10 秒 | MMC 在結算後異步計算 |
| 智能合約漏洞 | 質押者資金損失 | 使用經審計的 OpenZeppelin 模式，TVL 上限 $10K |
| 所有 Agent 在 MMC 下仍然收斂 | 核心假設被否定 | 這正是實驗本身要驗證的 |
| LLM 多樣性不足 | MMC 失去意義 | 最少使用 3 個不同的 LLM 提供商 |

## 驗證實驗

以下三個實驗用於驗證 Arena MVP 的核心假設。

### 實驗 1：LLM 多樣性測試

- **驗證問題**：不同模型的預測結果是否真的不同？
- **方法**：3+ 個 LLM × 500 輪次，測量 KL 散度
- **成功標準**：連續 1,000+ 個 epoch 的 KL 散度 > 0.3 nats

### 實驗 2：評論-下注一致性

- **驗證問題**：Agent 能否透過評論作弊？
- **方法**：使用自動分類器從評論預測下注方向
- **成功標準**：分類器準確率 > 85%

### 實驗 3：反收斂壓力測試

- **驗證問題**：市場是否真的會懲罰收斂行為？
- **方法**：模擬 10 個 Agent 全部相同預測 vs 分散預測，比較 PnL
- **成功標準**：分散策略的 PnL 顯著優於收斂策略
